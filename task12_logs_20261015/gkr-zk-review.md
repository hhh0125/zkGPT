## Findings

### M1 — Required GKR-specific coverage is incomplete

`work/src/main_gkr_zk_tests.cpp:13-82` builds one ZK proof. It compares prover/verifier challenge traces and mutates a normal terminal at index 0, but does not test fresh ZK proof randomness, explicitly assert the permitted ZK challenge-label sequence/absence of legacy round labels, or mutate the prior layer's `terminals[1]`/`terminals[3]` that feed the next normal/FCONN claims. Mutating `matrix_v.product.st` tests product verification; it does not independently exercise substitution of its inherited initial commitment or a valid local endpoint relation inconsistent with Lasso. The public output test changes only the statement, so it tests equality with the proof field rather than independent evaluation of the fixture output at the ZK output point.

The only ZK circuit fixture uses two-phase Sqr parents and four FCONN layers. It does not exercise one-phase normal layers, zero-round GKR sessions, or a composed zero Lasso mapping factor. The foundation zero-factor and L=0 evidence is useful and the inspected GKR code multiplies correctly; it is not GKR branch coverage. Existing legacy mutation coverage likewise does not replace coverage of the new hidden commitment relations.

Add focused GKR tests for the explicit brief requirements (fresh row/proof randomness, expected masked-only challenge labels, inherited u1/v1 mutations, and independent public output correctness), plus relevant one-phase/zero cases. A second independently generated proof changes hidden rows and therefore the output challenge; compare appropriate randomness-bearing messages and verify each output at its own point. Do not require its public output evaluation to stay identical. Keep the reported 14 independent cases exactly scoped as they are now.

### M2 — Public model dimensions are narrowed before validation

`work/src/gkr_verifier.cpp:101-110,807-813` accepts `WitnessShape` dimensions as `size_t`, then passes sequence/hidden/MLP dimensions to `ceilPow2BitLength`. The helper takes `u32` (`work/src/utils.cpp:23-26`). Neither the new statement decoder (`gkr_zk_serialization.cpp:126-130`) nor this metadata validator imposes an upper bound before that conversion.

On the evidenced 64-bit target, a declared dimension `2^32 + d` is interpreted by the arithmetic dimension helper as `d`; a multiple of `2^32` becomes zero and produces -1 before conversion to unsigned. The model metadata is transcript-bound, so this is not a replay collision or an established arithmetic forgery, but an unsupported large shape can be interpreted as a different small shape. It violates the intended model/circuit dimension boundary and makes validation rely on later incidental checks.

Reject unsupported sequence/hidden/MLP dimensions before narrowing (consistent with the 30-bit supported materialized dimensions), or use a checked size_t helper and explicitly validate its result. Validate input log size against the trusted input layer early. Add boundary rejects for `2^32`, `2^32 + fixture_dimension`, and values just above the supported cap. The byte decoder itself remains allocation-bounded; this finding is semantic metadata validation, not a demonstrated unbounded allocation attack.

### L1 — ZK local failure diagnostics still expose raw claims

`work/src/gkr_proof_builder.cpp:776` prints `cur_claim` and `previousSum`; `:849-851` prints the raw terminal expectation and actual sum when local consistency fails. These are reachable in ZK mode and are witness-dependent. They do not enter the encoded proof or the successful transcript, so this is not a successful-proof leakage finding. Guard or redact the scalar values in ZK mode before treating service logs as public; layer/round/error category is sufficient. Private local diagnostics are a separate boundary that should be documented if retained.

## Soundness/privacy and implementation inspection

- **Public prefix.** `gkr_verifier.cpp:425-475` binds protocol/curve, circuit fingerprint, model shape, original production generator descriptor, val0 dimensions and every hidden row, then ZK version/context/layout/scalar suite, before output challenges. Hashing the legacy metadata encoder here does not replay a legacy proof: it contains public metadata only. Output evaluation is intentionally appended after deriving its point and remains explicit public leakage.
- **Optional builder mode.** An explicit nonempty context selects ZK mode. Both legacy proof and statement getters reject in that mode. Separate proof types contain masked rounds, points, and Sigma responses rather than legacy raw endpoints/IPA final witnesses. Empty context still means legacy mode for compatibility; callers wanting ZK must use the typed getters and supply a nonempty externally chosen context.
- **Normal layers.** `gkr_proof_builder.cpp:753-882` starts one degree-2 session covering both phases and feeds the real `sumcheckUpdate1/2` evaluations at 0/1/2 into it. Returned challenges drive the existing folds. The four endpoint representation proofs precede the three products; each product's right operand has opening provenance. The verifier uses the existing public `computePredicates` and the same three-product/two-linear combination. Terminal relations precede alpha/beta. The next initial commitment is the homomorphic combination of the same u1/v1 commitments, not a fresh unauthenticated claim.
- **FCONN.** Both existing `sum_check_product` calls are preserved. ZK masking is inside that existing fold loop and suppresses raw coefficients/final_f/final_g. The two sessions start from the preceding exact u1 and v1 commitments. Public n/k mapping is reconstructed by the verifier; m is checked by session shape against model-derived rounds. Each pair of hidden endpoints has representation knowledge and product verification. FCONN secondary claims are checked as identity commitments, and the first pair's shared terminal aliases are checked.
- **Lasso.** Both parent paths' input and weight endpoints enter the same sigma sum; the second-path commitments are not dropped. The optimized folding workspace and its release remain in use. The independent verifier recomputes the mapping scalar from public wiring/points/sigmas. It finishes against `input_commitment * mapping` and opens that exact input commitment against the statement rows. No division occurs when mapping is zero. One-phase v1 is enforced as public zero; other absent source terms receive zero public coefficients and are not used as live claims.
- **val0 ownership and basis.** Constructor rows are copies of `comm.comm`, randomized by fresh rho H; `p->cc` rows are not mutated. Opening uses a borrowed `HyraxFrWitnessView(comm.w, value_count)` with private row blinders and the same randomized public rows. Production generators are checked against `getGeneratorSet`. The foundation collapse allocates columns rather than another full val0 vector. Lasso workspace is released before opening, with joined workers preserved. The local legacy row-copy variable in the opening function is unused by the ZK proof and is not serialized.
- **Raw branches.** Normal raw coefficient storage/appends, FCONN raw rounds/endpoints, final layer scalar appends, raw Lasso input evaluation, and the legacy public-evaluation opening are gated out of ZK mode. `appendQuadratic` additionally throws in ZK mode. Raw values still exist privately for consistency checks; see L1 for the failure-log exception. The ZK codec has no raw `input_evaluation`, legacy `final_witness`, or scalar endpoint fields. The public output and public mapping factor are the intentional exceptions.
- **Limits and codecs.** Distinct statement/proof magic/version, canonical scalar/point decoders, exact nested sizes, and trailing-byte checks are present. Statement/proof bytes cap at 2/128 MiB; public circuit layers cap at 4096; individual dimensions cap at 30 in the proof codec; normal mask rounds derive from the trusted circuit; matrix encoded rounds are capped at 30 before allocation. The final opening length derives from the trusted input layer. Reader::bytes checks remaining bytes before copying; Writer::bytes uses the existing bounded raw writer. The generic mask cap of 60 uses O(L) coefficients and field powers, with no 2^60 allocation. Materialized degree-1/degree-3 prover paths remain capped at 30. Trusted public circuit structure remains a caller precondition; the direct verifier API is not an arbitrary circuit parser.
- **Independent boundary.** `main_gkr_zk_verify.cpp` reconstructs public wiring through `tests/gkr_public_fixture.cpp`, instantiates no prover or witness, takes expected context from argv, and derives the fingerprint from its compiled public circuit. It does not trust the artifact's own fingerprint as authority. The generic verifier accepts a caller-supplied statement; callers must compare expected application context/statement themselves, as this executable does. The openat trace shows public statement/proof files and runtime/system files, with exit 0 and no private witness/model file reads on that execution.
