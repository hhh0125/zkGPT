# OPT3-B evidence recovery

No recovery build or new proof generation is performed by archive verification. These instructions are for a separately authorized recovery on a replacement system/new empty destination; do not overwrite the active Linux workspace or create a sibling source copy as routine validation.

1. Check MAPPING_WINDOWS_ARCHIVE_VERIFIED.json, then the eventual WINDOWS_ARCHIVE_VERIFIED.json and FINAL_DELIVERY_VERIFIED.json. Verify each container SHA against its receipt and every member against its manifest before use. A missing final receipt means that corresponding archive has not been accepted.
2. `mapping-stage-source-and-evidence.tar.gz` contains the complete current source, dependencies, configuration, baseline/current ELFs, public mapping inputs, positive/negative logs, component proof and deterministic transcripts. `mapping-restored/` is its Windows SHA-verified extraction. `before/` contains the exact391-file OPT3-A+No-FullBase baseline. Use R7_OPT3B_MAPPING_DIFF.patch only as the separate6-file incremental description; GitHEAD alone cannot recover the uncommitted baseline.
3. The eventual `opt3b-full12-source-and-evidence.tar.gz` contains `source/`, `dependencies/`, `runtime/`, `configuration/` and complete `evidence/full12/` plus `evidence/kernel/`. Its new public Proof is downloaded separately as `full12-opt3b-v1.fsproof`, SHA recorded in R7_OPT3B_FULL12_RESULT.json and archive receipt. Statement, raw P/V, coverage/layout, message audit and five-second resource logs accompany it. Never substitute an old Proof.
4. On a replacement Linux system, place source/src and source/CMakeLists.txt in the new root. Materialize dependencies/deps and dependencies/3rd/mcl at root/deps and root/3rd/mcl. Copy configuration/reports into root/reports, preserving relative paths: R6A/full12-model-manifest-v1.txt, original fixed10chunkAnchor and the original Full12 signed64 public X/Y. Recreate all120 parameter paths from PARAMETER_RESTORE_MAP.json using the verified Windows migration-20261020/restore-cas bytes; rehash every path. Keep Anchor SHA/pin unchanged. Dependencies and runtime identities/tool versions are recorded in TOOLCHAIN_AND_RUNTIME.json; the archive is not an offline OS image.
5. Configure a fresh Release build using the recorded compiler/system libraries and root/deps/cnpy include/static library paths. Do not reuse archived absolute CMakeCache paths as a new build cache. Current executables require Linux and a filesystem supporting O_TMPFILE in the execution directory. The public mapping cache is regenerated from the verified mappings; its anonymous file and all private Witness/blinds are deliberately absent from archives.
6. If separately authorized to verify, use a fresh verifier process with a newly opened read-only Statement FD, disk Proof and exact context `zkGPT/R7/Full12/opt3b-mapping/20261030/v1`; see full_run_remote.py for FD/environment setup. Suite remains Full12 FS v2. No Prover private state is needed. Any fresh proving requires a newly computed real R6 Witness and explicit task authorization; archive/restore checks do not authorize it.

Retention: keep all historical code, Proofs, Anchors, logs and these verified archives. No cleanup or remote deletion is authorized here. Credentials/private keys are never in the evidence. Security status remains FS_NIZK_CANDIDATE / BLOCKED_CRYPTOGRAPHIC_DESIGN / may_enter_stage2=false.
