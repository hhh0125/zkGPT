# Ownership and protocol compatibility

No global commitment layout, numericalProfile, Sumcheck order, Lasso binding, proof wire format or Fiat-Shamir transcript redesign. The exact changedsource list and original/afterbytes are in SOURCE_CHANGE_MANIFEST and sourcepatch.

1. Previously val0 was padded with zero, copied into raw cc.w, then copied into a caller vector. The shared path constructs one paddedzero vector and copies each logical val0 element into the same index, calling the SAME prover_commit with the same generators/domain/threadcount. Every logical field and zero tail is identical. Row commitments and GKR input identity are consequently equal. Publication moves ownership only after workers join; fault injection tests preserve priorowner for prepublicationfailures and retain validnewowner if optional diagnostics fail afterpublication.
2. The engineering input witness reserves exact builder-derived actual capacity once and checks finalsize equals this hint. It does not truncate, expand an integerdomain, or alter witness computation. val0 is no longer temporarily padded/compacted. GKR reads and all actual/padded coordinates remain unchanged. Legacy rawcommit remains default for other callers; old R5B blocks1 guard is unchanged.
3. Caller master becomes const vector& to the prover-owned padded vector. Downstream commitments, GKR/Lasso mapped checks, bridge and unifiedinput continue receiving the same ordered field values. This is restricted to the audited engineering paths; cc.w retains its legacy nonconst API type, and no claim of universal immutability for arbitrary external code is made. Small realcommit/GKR test asserts allvalues unchanged across builder use and checks caller/cc addressidentity; actualoneblock shows sameaddresses and original accepted proofbytes.
4. GKRBuilder borrows the same pr.C object. Added R2 logging and identity assertion introduce no transcript calls or changes to statement, challenges, arithmetic, messages, or queryorder. Memory budget changes are outside mathematicalprotocol inputs. mapped_input.cpp is unchanged inOPT2; direct span subtraction guards are exercised under ASan/UBSan, including SIZE_MAX offset/count, actualend, countsum, repeatednegativebias and everypaddingtail.
5. Given identical ordered padded witness and generators, commitments match. Then identical statement, challenges and deterministic arithmetic imply by induction identical GKR, Lasso, mapped Sumcheck, bridge and opening messages. This code-level argument explains compatibility; tests corroborate it. Freshoneblock statement/proof bytes are compared with both OPT and original independently acceptedR5B, and a fresh independentVerifier must ACCEPT.
