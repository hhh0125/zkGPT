# Route B Phase B1: standalone Lasso/Surge prototype

This implements Lasso Figure 6 / Surge Figure 5 with arbitrary explicit tables (`c=1`) and additive SOS tables (`c>=1`). It is an unindexed, non-hiding research prototype, capped at 256 queries and 256 table entries. It does not replace strict-v4 LogUp, connect to C0, integrate with GKR, or provide complete zero knowledge.

From the project root:

```sh
cmake -S . -B phase_b1_20261017/build -DCMAKE_BUILD_TYPE=Release -DZKGPT_BUILD_LASSO_PROTOTYPE=ON
cmake --build phase_b1_20261017/build --target lasso_tests lasso_verify -j4
ctest --test-dir phase_b1_20261017/build -R '^route_b_lasso_' --output-on-failure
```

The second CTest entry uses Python 3 standard library only, generates fixtures, and invokes a separate verifier process for every positive/negative case. Test outputs live beneath `build/src/lasso/{fixtures,independent-fixtures}`. Without Python, run the verifier manually against fixtures generated by `lasso_tests DIRECTORY`.

The verifier accepts exactly two inputs: a verifier-approved instance file and the proof. A table or instance supplied by an untrusted prover is not a trust anchor.

```sh
phase_b1_20261017/build/src/lasso/lasso_verify \
  phase_b1_20261017/build/src/lasso/fixtures/nonpower_repeated.instance \
  phase_b1_20261017/build/src/lasso/fixtures/nonpower_repeated.lasso
```

For application use, initialize MCL with `mcl::bn::initPairing(mcl::BN254)` and its default hash-to-curve mode, then call:

```cpp
auto instance = route_b::lasso::makeInstance(
    {Fr(3), Fr(5), Fr(8)}, 5, {2}, false, "explicit-example");
auto proof = route_b::lasso::prove(instance, {Fr(8), Fr(3), Fr(5), Fr(8), Fr(3)});
auto wire = route_b::lasso::encodeProof(proof);
// In the independently running verifier:
route_b::lasso::VerifiedLookupClaim claim;
std::string error;
bool accepted = route_b::lasso::verify(
    approved_instance, route_b::lasso::decodeProof(wire), &claim, &error);
```

Include `lasso_prover.hpp`, `lasso_verifier.hpp`, and `lasso_serialization.hpp`. `VerifiedLookupClaim` exposes the instance digest, query commitment, row point and authenticated evaluation. It makes no assertion about any external witness or C0.

The field/curve IDs name MCL BN254, whose scalar modulus is frozen in `lasso_types.hpp`. MCL BN_SNARK1 is a distinct field and is rejected. Backend ID 1 is a dedicated one-row vector IPA adapter over existing generic Hyrax IPA functions. It does not use the legacy 2D Hyrax MLE reshaping API. Openings are individual; batching is not implemented.

All coordinates use low-bit-first Boolean indices. Non-power-of-two query padding repeats T[0] and zero address; a masked IPA enforces it. A separate validity memory excludes padded table addresses. This memory enumerates the padded table, so this implementation does not achieve the original SOS sublinear-in-table bound. Additive SOS supports unequal bit partitions as a documented adaptation; it does not support arbitrary user-defined g polynomials.

See `PROTOCOL.md` for P/R/D/I provenance, exact memory invariant, multiplication-tree reduction and Fiat–Shamir schedule. Wire format and composition are engineering choices: **论文未明确给出，不能从论文直接推出**. Mutation tests and regenerated attacks are evidence for the checked cases, not a proof of universal malicious-prover resistance or a new Fiat–Shamir security theorem.
