# Windows 构建修改说明

## 背景

`run_msm/build_bn254_msm_backend.ps1` 已切换为使用本目录中的 mcl：

```text
C:\Users\tanyt\Desktop\program\zkGPT\3rd\mcl
```

首次构建时出现以下错误：

```text
bint-x64-win.asm(1) : error A2088: END directive required at end of file
error C3861: “get_sub”: 找不到标识符
error C3861: “get_mulUnit”: 找不到标识符
error C3861: “get_mulUnitAdd”: 找不到标识符
LINK : fatal error LNK1181: 无法打开输入文件“obj\fp.obj”
LINK : fatal error LNK1181: 无法打开输入文件“lib\mcl.lib”
```

## 根本原因

本目录的 `mklib.bat` 原本直接调用 `python3`：

```bat
python3 src\gen_bint_header.py ...
python3 src\gen_bint_x64.py ...
```

当前 Windows 环境可以运行 `python.exe`，但进入 Visual Studio Developer Command Prompt 后无法找到或运行 `python3.exe`。

批处理中的输出重定向会在 Python 启动前创建或截断目标文件。因此 Python 启动失败后，以下三个生成文件变成了 0 字节：

```text
include\mcl\bint_proto.hpp
src\bint_switch.hpp
src\asm\bint-x64-win.asm
```

空的汇编文件导致 MASM 报缺少 `END`，空的头文件导致 `get_sub`、`get_mulUnit` 和 `get_mulUnitAdd` 等生成接口缺失，随后又引发目标文件和静态库缺失等连锁错误。

此外，这一版 `mklib.bat` 默认只生成 `mclbn384_256.lib`，而 BN254 MSM 构建脚本需要 `mclbn256.lib`。

## 对 `mklib.bat` 的修改

### 1. 支持外部传入 Python 的绝对路径

脚本现在使用 `MCL_PYTHON` 环境变量：

```bat
if not defined MCL_PYTHON set "MCL_PYTHON=python.exe"
```

生成命令改为：

```bat
"%MCL_PYTHON%" src\gen_bint_header.py ...
"%MCL_PYTHON%" src\gen_bint_x64.py ...
```

`run_msm/build_bn254_msm_backend.ps1` 会在 PowerShell 中解析 `python.exe` 的绝对路径，然后将其作为 `MCL_PYTHON` 传入 Visual Studio 的 `cmd.exe` 环境。

### 2. 增加逐步错误检查

Python 生成、MASM 汇编、C++ 编译和静态库生成步骤之后均增加：

```bat
if errorlevel 1 exit /b 1
```

任何步骤失败时会立即停止，避免错误继续传播到后续链接阶段。

### 3. 恢复 `mclbn256.lib` 构建

静态库构建流程增加：

```bat
cl /c %CFLAGS% src\bn_c256.cpp /Foobj\bn_c256.obj
lib /nologo /OUT:lib\mclbn256.lib /nodefaultlib obj\bn_c256.obj lib\mcl.lib
```

DLL 分支也增加了对应的 `mclbn256.dll` 和导入库生成步骤。

原有的 `mclbn384_256` 构建流程予以保留。

## 构建结果

修复后已成功生成：

```text
lib\mcl.lib
lib\mclbn256.lib
lib\mclbn384_256.lib
```

被清空的生成文件也已恢复为有效内容：

| 文件 | 验证时大小 |
| --- | ---: |
| `include/mcl/bint_proto.hpp` | 66,514 B |
| `src/bint_switch.hpp` | 17,768 B |
| `src/asm/bint-x64-win.asm` | 77,407 B |

使用本目录中的 mcl 后，以下程序均已成功编译：

```text
run_msm\bin\bn254_pippenger_opt_v7_split.exe
run_msm\bin\bn254_g1_tools.exe
```

## 重新构建方法

在工作区根目录运行：

```powershell
powershell.exe -ExecutionPolicy Bypass -File run_msm\build_bn254_msm_backend.ps1
```

外层 PowerShell 脚本会完成以下操作：

1. 定位 `python.exe`；
2. 初始化 Visual Studio x64 编译环境；
3. 在静态库缺失时构建 mcl；
4. 编译 BN254 MSM 后端；
5. 编译 BN254 G1 工具。

## `mclbn256` 与 `mclbn384_256` 的用途

| 库 | 基域容量 | 标量域容量 | 主要用途 |
| --- | ---: | ---: | --- |
| `mclbn256.lib` | 256 bit | 256 bit | BN254 |
| `mclbn384_256.lib` | 384 bit | 256 bit | BLS12-381 等需要 384-bit 基域的曲线 |

当前 `msm_v7_split.cpp` 初始化的是 `mcl::BN254`，并使用 256-bit 的 mcl 类型配置，因此应继续链接 `mclbn256.lib`。头文件的字段容量配置必须与所链接的库保持一致，不能随意混用。
